# Lessons Learned

## v0 lessons

### 1. Public value beats invisible activity
A private flurry of commits does not build trust.
Public artifacts with clear utility do.

### 2. Small, reviewable scope is a feature
A narrow improvement with clear reasoning is more credible than a broad autonomous claim.

### 3. Documentation is underrated leverage
README quality, architecture notes, and failure analysis create visible technical signal fast.

### 4. Taste is part of the product
The system should encode engineering restraint, not just tool execution.

### 5. Approval-first workflows scale trust better than full autonomy
The best public workflow is usually:
propose -> approve -> execute -> explain
